编程代理怎样变成视频导演

看起来像“人工智能做了一整部片子”的演示，底下是一个规划者在写结构化文件，一个程序员在调用工具，一个批评者在读回帧、转写和数字。这一页把它拆开：规划、技术选择、编排、自检、修改，以及多代理——并写明证据实际支持什么。

1 · 创作规划：从一句话到一份制作计划

代理的第一件工作，是把一句含糊的请求变成结构化、可检查的产物。一份好计划大部分是数据：

产物内容大语言模型做这个有多可靠？
创作简报 / 目标观众、语气、长度、平台、关键信息、必须有的东西好，如果它会问或写出假设 实践
研究笔记带来源的事实有网页搜索和引用时好；凭记忆不可靠（编出来的数字）实践
剧本 / 口播词，大约每分钟 130–160 个英文词，或中文约 240 字强——这是大语言模型的本行；仍要核对事实，还要人听一遍
分镜每个镜头一帧描述（或生成的静帧）描述好；空间构图和视觉口味较弱
镜头表每个镜头：时长、类型、技术、摄像机、资产、声音提示作为结构很强；时长以后必须从音频量出来
风格圣经调色板、字体、观感、参考、镜头语法、声音调色板中；不给参考就容易泛
验收标准可测试的检查：“没有文字瑕疵”、“−14 LUFS ±1”、“所有事实有来源”强——也是后来自检的关键
日程和预算任务顺序、并行、接口成本估计结构好；成本估计需要真实价格表

2 · 每个镜头选技术

同一部片子里的不同镜头可以——而且通常应该——用不同的技术。代理可以应用的一张路由表：

如果这个镜头需要…分给为什么
精确的文字、数字、公式、图表、界面B 二维代码只有渲染能保证正确
物理或技术上准确的运动（轨迹、机构）B 三维加模拟按构造就是对的
照片级气氛、自然、人群、“电影感”空镜A 生成视频（从检查过的关键帧做图生视频）到写实最便宜的路
真实事件、真实产品、真实的人C 已获许可的素材或屏幕录制真实性和权利
一个出镜的人A4 数字人（须有同意）或录的真人—
口播下面便宜、平静的东西C1 静帧加慢速平移，或视差成本低，控制全
写实观感加精确运动D2 三维块面 → 视频生视频B 的控制加 A 的观感

让混用的镜头保持一致是设计任务：所有叠层用一套调色板和字体系统；每个镜头用同一套调色或查找表；参考图（角色设定、产品照片）传给每一次生成调用；三维里和提示里用同一套镜头语法；一条音乐底和房间底噪把切换粘在一起。实践

3 · 工具编排：代理实际怎样驱动软件

机制例子强项弱项
生成源代码，再跑它写 Remotion 合成、Manim 场景或 Blender 脚本；用命令行渲染确定、可做差异、可审阅工具链要装好
命令行工具FFmpeg、ffprobe、Whisper、Blender -b通用、可脚本语法错误；必须校验输出
云接口 / 软件开发工具包提交视频任务、轮询、下载用得到最好的模型；不用显卡成本、速率限制、模型变更、异步的复杂
MCP 服务器Blender MCP、Resolve MCP、厂商 MCP工具像带类型的函数；好接包装薄；质量不一；任意代码执行的安全问题
代理技能Remotion / HyperFrames / video-use 技能写进专家经验和硬规则（例如“字幕放在滤镜链最后”）好不好取决于作者的经验
子代理每个动画或每个批评方面一个子代理并行、上下文集中协调开销；约束不够时风格不一致
图形界面自动化在没有接口的应用里点击封闭应用的最后办法脆、慢，常常违反条款

三档自主程度

直接用工具

代理在对话里一条条跑命令。起步快，难复现：“流水线”只存在于聊天记录里。

写成脚本的工作流

代理把流水线写成代码（带缓存步骤的构建脚本或有向无环图）再跑。可复现、可恢复；改动是代码差异。

自主循环

代理跑流水线、检查输出、不请示就改计划或代码——在预算之内，并有批准门。

稳的组合是“写成脚本的工作流，外面再套自主循环”：代理用判断去改计划和代码，但每一次制作运行都是一次可复现的构建。这和优秀软件团队用持续集成的方式一样。推断

4 · 自主质检：代理怎样“看”自己的视频

当前的编程代理大多不能像你那样看视频。Claude 文档里的接口输入是图像（没有视频），Gemini 的接口接受视频，但默认按每秒 1 帧抽样。所以检查是一组合起来的、更便宜的局部视图。已核对（Claude 视觉文档，Gemini 视频文档）

方法抓住什么漏掉什么成本可靠程度
元数据探测（ffprobe）时长、帧率、分辨率不对，缺音频流任何视觉问题约 0精确
信号检测（黑场、冻结、静音、响度、削波）黑帧、冻帧、静音空隙、响度偏离内容错误约 0精确
抽样帧 → 视觉模型构图、可读性、错误物体、风格不符、文字瑕疵（加文字识别）运动、闪烁、样本之间的单帧故障、时机Claude：1080p 一帧约 1560 词元（标准档）→ 60 帧约 9.4 万词元静帧好；取决于怎么抽
聪明的抽样（场景变化、切口前后、提示点帧、胶片条或接触印样）坏的切口、转场、已知事件上的叠层时机选定点之间的问题同上，但更对准比均匀抽样好得多 实践
整段 → 视频模型（Gemini）叙事流动、粗的连续性、粗粒度的声画不符亚秒事件、时间顺序的细微处每秒视频约 100–300 词元中等；时间推理弱（见下）
对照参考（嵌入、脸或身份相似度）角色或产品相对参考图的漂移为什么漂低（本地模型）当警报很好
帧上的文字识别屏幕上的错字或乱码—低干净文字上高
语音识别对照剧本漏词、读错、音乐盖住人声、字幕错误语气、情绪低高
时间检查提示点对事件帧、字幕同步、声画偏移—约 0精确（如果事件有记录）
简报清单审计缺了必须的内容、长度、信息质量低标准可测时好
人来审口味、情绪、隐蔽的不对、品牌契合长审会疲劳你的时间仍是金标准
当前的人工智能评判真正注意不到什么
  • 时间顺序和细微运动。在 TOMATO 基准上，人得分 95.2%，最好的模型 37.9%；把帧打乱几乎不伤模型（37.8% → 28.5%），说明它们靠单帧。已核对（arXiv 2410.23266，2024 年前后的模型）。Vinoground 发现时间反事实上人约 90%，GPT-4o 约 50%（arXiv 2410.02763）。
  • 样本之间的一切：单帧故障、闪烁、短暂的变形。
  • 差几帧的口型漂移、声画偏移、让人觉得“不对”的节奏。
  • 明显失败之外的物理是否说得通。
  • 它自己的盲点：评判模型和产出时用的是同一族，会有偏差；Code2Video 用 Gemini 2.5 Pro 既当循环里的批评者，又当评测评判。推断

令人鼓舞的是，看见渲染输出的评判比只读代码的好得多：一项研究报告，看渲染视频的视觉语言模型评判与人的一致率 87.8%，只看文字的评判是 69.1%（SimuScene，arXiv 2602.10840，附录）。已核对

一套实用的检查栈，从便宜的开始：探测 → 检测器 → 语音识别和文字识别 → 对准的帧送给视觉模型 → 一次整片浏览 → 人。上一层过了，下一层才跑。推断

5 · 迭代改进：从批评到具体改动

难的一步是把“这看起来不对”翻译成一次编辑。两种修法的行为完全不同：

问题具体修改种类
镜头运动太快关键帧跨度从 2 秒拉到 3.5 秒；缓入缓出确定的 B
场景太暗提高主光或曝光；或后期加 0.5 档确定的
标签压住助推器移动叠层锚点；只重合成 V2 层确定的
口播比画面早挪段的起点；或把动画重定到那个词的时间戳确定的
说话时音乐太响说话区间压低 6 分贝；只重混音频确定的
转场弱换切口类型（叠化 → 匹配剪辑）；调时长确定的
生成镜头有融化的手或错的标志换种子、收紧提示重生成，或从改好的静帧做图生视频；或切短有概率的 A
角色和第 3 镜看起来不一样带参考图或 LoRA 重生成；或换成渲染镜头有概率
生成镜头的构图弱先把起始帧设计成静帧，再图生视频部分确定
镜头之间连续性断了末帧接到首帧；插入切走的镜头；重排混合

只重渲改过的部分。把制作当成构建系统：每个镜头的输出是它的输入的函数（代码、参数、资产、模型版本、种子）。给输入做哈希；哈希没变就复用缓存。口播一改 → 只重建受影响的镜头和混音。这和 make 或 Bazel 是同一个想法，用在媒体上。推断

知道何时停

  • 所有验收标准都过了（所以要事先写成可测的标准）。
  • 每个镜头的迭代上限——video-use 把自检封在 3 遍；之后交给人。已核对（video-use SKILL.md）
  • 金钱和时间上的预算上限，记在成本账里。
  • 收益递减：批评者的问题已经是口味，或和先前的批评矛盾（来回振荡）。
  • 人的门：代理交出成片，并列出已知的妥协。实践

6 · 多代理制作：证据怎么说

角色扮演剧组（编剧、导演、动画、剪辑、质检……）在研究和营销里很流行。实际有支持的是：

证据发现强度
FilmAgent（arXiv 2501.12909）虚拟三维里的多代理剧组，人评 3.98，单代理 3.04弱到中：15 个故事点子，评分人少
Code2Video（arXiv 2510.01174）规划者加写代码的加批评者：美学/测验 87.9/86.0，直接生成代码是 37.8/40.0（Claude Opus 4.1）。去掉规划者伤得最重；去掉批评者伤得较轻中：说明分解要紧；评判是语言模型
TheoremExplainAgent（arXiv 2502.19400）整片成功率因模型差很多（o3-mini 93.8%，Claude 3.5 Sonnet 2.1%）；主要失败是代码幻觉和版式重叠中；2025 年前后的模型
一般的代理研究（Kim 等，Cemri 等）多代理帮助可并行的任务，伤害顺序任务；多代理框架因协调问题失败率高强，但不是针对视频的
建议

一个强的导演代理拥有计划和项目文件；它把专家子代理派去做并行、规格清楚的工作（渲染第 4 镜、写第 7 段动画、批评节奏、批评可读性），每个都有窄的简报和风格圣经。不要让对等的代理委员会辩论创作选择。从业者的仓库是这个模式（video-use：并行的动画子代理；product-launch-video：四个并行的批评者）。推断，由上面的证据支持。

代理怎样共享状态

  • 文件，不是聊天：简报、剧本、镜头表、风格圣经、时间线、清单、决策日志——都在版本控制下的项目文件夹里。媒体二进制放在按内容寻址的存储或 Git LFS。实践（video-use 保留 project.md、edl.json、缓存的转写、一个 verify/ 文件夹）
  • 代理之间的契约：子代理收到镜头规格加风格圣经，必须在已知路径交回一个文件，外加一份短报告。
  • 每个文件一个写者：导演合并；子代理提议。

代理离自主导演还有多远？

今天，可靠

规划文档、带来源事实的剧本、代码驱动的动画、组装、字幕、按规格混音、客观质检、局部重渲、保住一个可复现的项目。

今天，要有人看着

挑选生成镜头、根据帧判断画面质量、迭代风格、跨技术给镜头路由、剪辑实拍（计划要先批准）。

还不行

整部片子上一致的口味、可靠的时间判断、没有人挑选的长篇角色一致性、知道对你的观众来说什么叫够好。

推断，依据第 11 页和第 14 页。
