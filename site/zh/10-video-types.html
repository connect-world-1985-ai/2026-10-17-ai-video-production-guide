第 10 页 · §10 + 交付物 F — 按视频类型的制作策略

十二种视频类型，十二种做法

一套对数学讲解片完美的技术栈，对音乐视频毫无用处。这一页说明每一类在技术上差在哪里、用什么来做、编程代理今天能自动化到哪一步，以及质量怎么评判。

逐类说明

1 · 教育与讲解动画
不同在哪
正确和清楚胜过真实感。观众必须一次跟上一个想法；文字、符号和示意图必须精确。
方法
代码驱动的二维（数学和示意图动画），先有口播再定时间，偶尔用静帧或生成的空镜交代背景。
工具（类别）
Manim 风格的 Python 库；React/HTML 视频框架；语音合成 + 强制对齐；FFmpeg。
声音
口播是骨架；轻音乐底；音效很少。
自动化
高——记录最充分的代理结果就在这里（Code2Video、TheoremExplainAgent、Remotion/HyperFrames 技能）。
限度
在 TheoremExplainAgent 里，版面重叠和代码错误是最主要的失败；教学品质仍然需要老师的眼睛。
怎么评判
准确性、可读性、节奏；Code2Video 的 “TeachQuiz” 想法——看完之后观众能不能回答问题？已核对 的概念（arXiv 2510.01174）
2 · 科学与工程可视化
不同在哪
画面必须是真实数据或物理的函数。看起来像那么回事、但羽流或轨迹是错的，那是缺陷，不是风格。
方法
模拟 → 三维渲染（Blender、ParaView）或二维图；注释叠层；生成式视频只用于非技术性的背景。
自动化
搭建和渲染可以很高；正确性需要领域审阅。
怎么评判
对每一条主张做专家审阅；数据出处；单位和比例。
3 · 专业商务演示
不同在哪
品牌合规（字体、颜色、徽标）、数据图表、演讲者或口播，常常从已有幻灯片或文档生成。
方法
模板驱动的二维（幻灯片 → 动画场景）、从数据做图表、语音合成或数字人出镜、字幕。
自动化
高。主要风险是看起来很普通；用一套强的品牌套件来修。
怎么评判
品牌清单、数据准确性、信息是否清楚、时长。
4 · 电影感与照片级视频
不同在哪
灯光、镜头、表演、连续性和情绪。每一帧都被当成一幅画来看。
方法
先关键帧：带参考的设计静帧 → 每个镜头图生视频 → 多条 → 人来挑选 → 剪辑、调色、声音设计。专业的人工智能影片大量靠挑选。
自动化
低到中。代理可以跑流水线、生成候选并预筛；挑选和口味仍是人的。
限度
跨镜头的角色一致性、手和物理、片段长度；多条的成本。
怎么评判
人来审；连续性表；参考身份核对。
5 · 营销与广告
不同在哪
产品外观必须精确、法律上的主张、品牌语气、很多变体（格式、语言、A/B 版本）。
方法
产品渲染或照片（精确）+ 生成的环境；模板化的变体；数字人或画外音的本地化。
自动化
中——变体生成非常容易自动化；主概念不是。
限度
生成模型会改徽标和产品细节；每个工具的商用条款；披露规则。
怎么评判
品牌与法律审阅、产品保真度核对、平台规格、上线后的效果指标。
6 · 社交媒体内容
不同在哪
竖屏 9:16，头 1–2 秒决定留存，烧进画面的字幕，节奏快，追热点。
方法
模板组装（素材库或生成的片段 + 语音合成 + 大字幕）、把长视频切成短片、带原生音频的短生成片段。
自动化
模板化格式可以很高（例如 MoneyPrinterTurbo 风格的流水线）；原创性是瓶颈。
怎么评判
开头钩子的力度、手机上字幕是否可读、安全区、平台对人工智能内容的标识规则。
7 · 纪录片风格的制作
不同在哪
可信度：真实画面、有出处的事实、克制。看起来像证据的生成图像会误导。
方法
资料影像和静帧（加上运动）、采访、渲染的重构、生成的气氛明确作为图示；口播和配乐。
自动化
中：研究和组装可以；资料许可和编辑伦理需要人。
怎么评判
事实审计、权利审计、对重构的披露。
8 · 动画叙事
不同在哪
角色必须在几十个镜头里保持设定（on-model）、表演、对白、故事结构。
方法
生成式：角色设定表 + 参考 / LoRA → 关键帧 → 图生视频；或带动作捕捉的三维角色；或二维绑定。多智能体研究系统（MovieAgent、ViMax、FilmAgent）瞄准的就是这个。
自动化
低到中；研究级系统存在，但关于长片质量稳定的证据很薄。
怎么评判
角色一致性核对、故事审阅、观众测试。
9 · 数字出镜者与人工智能数字人
不同在哪
一个在说话的人；口型同步和自然的手势；多语言版本。
方法
数字人平台（剧本 → 视频）或开源的音频驱动模型；幻灯片和空镜合成在出镜者周围。
自动化
经平台接口可以很高。
限度
长镜头里的怪异瞬间；同意和肖像规则（厂商要求个人分身有出镜同意）。
怎么评判
口型质量（同步指标、人来看）、发音、观众信任。
10 · 音乐视频
不同在哪
歌是固定的，歌就是时间线；画面跟着节拍、段落和歌词。
方法
节拍 / 段落分析 → 镜头计划 → 生成或渲染的画面 → 卡点剪辑；研究系统 AutoMV 把这件事端到端自动化。
自动化
中：同步是机械的；美学上的连贯靠挑选。
怎么评判
同步是否准确、画面是否连贯、艺人是否认可。
11 · 产品演示
不同在哪
必须如实展示真实产品；界面经常改。
方法
脚本化的浏览器或应用自动化，无界面录制，缩放和光标高亮，口播，字幕；硬件则用渲染的产品镜头。
自动化
软件可以很高：界面一改就自动重录。product-launch-video（EveryInc）是一套有记录的 Claude Code 工作流。已核对
怎么评判
相对当前产品是否准确、界面文字是否可读、时长。
12 · 混合多种风格的制作
不同在哪
根本不同的来源之间要一致。
方法
强的风格圣经、一次调色、共用的字体、声音粘合；有意的风格转换。
自动化
中：路由和组装可以自动化；凝聚需要口味。
怎么评判
它像不像一部片子？人来审。

为什么一套技术栈换到另一类就会失败

  • Remotion/Manim 技术栈适合讲解片和产品演示，但做不出可信的人或风景。
  • 生成式视频技术栈能做出惊人的电影镜头，但对任何必须精确正确的东西（数据、界面、数学、物理、徽标）都是错的工具。
  • 数字人平台做对着镜头说话的人无可替代，做别的则用不上。
  • 模板视频接口能便宜地扩出社交变体，但讲故事会很普通。
  • 三维引擎给你完全的控制，但每一个新物体都变成一次资产制作。

推断

端到端工作流（交付物 F）

  1. 代理根据来源起草大纲和剧本；你批准。
  2. 按段落做语音合成 → 词的时间戳。
  3. 代理用代码框架写场景（Manim 或 Remotion/HyperFrames），每个场景的时长来自它的段落。
  4. 渲染预览；代理在提示点检查静帧，并修掉重叠。
  5. 音乐底、压低、响度；字幕来自时间戳。
  6. 最终渲染；语音识别核对；你审阅。

典型成本：几乎全是代理 token 加语音合成。所有类别里自动化最高。

  1. 代理为演示路径写一段浏览器自动化脚本（确定的、可重跑）。
  2. 高分辨率录制；记下每个动作的时间戳。
  3. 口播按动作日志来写；语音合成；时间。
  4. 代码框架在记下的时间戳上加缩放、高亮、标注。
  5. 批评一轮，看帧里的界面是否可读；界面若改了就重录。

  2. 混合：生成片段（原生音频可以）、带运动的静帧、动态字幕。
  3. 词级、烧进画面的字幕，落在平台安全区内。
  4. 做 3–5 个钩子变体；人来挑。
  5. 按平台规则给写实的人工智能生成内容加标识。

  2. 数字人平台接口（库存数字人，或已同意的个人分身）→ 出镜片段。
  3. 幻灯片和示意图用代码渲染；把出镜者和幻灯片合成。
  4. 翻译剧本 → 重新配音 → 每种语言做口型同步。
  5. 每种语言一份字幕；用该语言的语音识别做质检。

  2. 用图像模型加参考，为每个镜头做关键帧；你批准分镜。
  3. 每个镜头图生视频，3–4 条；代理用帧检查预筛；你来挑。
  4. 剪辑、调色、声音设计、配乐；对白用语音合成或原生音频。
  5. 连续性审阅；重生成弱的镜头。

自动化最低；生成花费最高；在这里代理是制作助理，不是导演。
