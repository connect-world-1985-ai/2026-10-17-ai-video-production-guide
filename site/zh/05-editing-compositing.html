剪辑、合成、精修与编码

后期是把分开做的镜头和声音变成一条视频的地方。对代理来说，它也是整条流水线里最确定、最好自动化的一段。

人们统称“剪辑”的四件事

剪辑（切开）

哪个镜头、什么顺序、多长、用什么转场。叙事和节奏。

合成

在一个镜头内部叠层：文字叠在影像上，示意图叠在渲染上，抠好的出镜人叠在背景上。

精修

调色、稳定、放大、帧率转换、降噪、字幕、终混。

编码与交付

按每个目标压进编解码器和容器（YouTube、社交 9:16、存档母版），带上字幕和元数据。

时间线是一种数据结构

每一种剪辑器——Premiere、Resolve、Final Cut、一个 JSON 视频 API、一条 FFmpeg 命令——表示的都是同一件事：

timeline:
  fps: 30, resolution: 1920x1080, duration: 120.0
  video_tracks:
    V1: [ {asset: shot01.mp4, in: 0.0, out: 6.5, at: 0.0, transition_in: none},
          {asset: shot02_render.mov, in: 0.0, out: 9.0, at: 6.5, transition_in: {xfade, 0.5s}} … ]
    V2: [ {asset: label_altitude.mov (alpha), at: 12.0, out: 4.0} … ]
  audio_tracks:
    A1 narration: [ {asset: vo_seg01.wav, at: 0.4}, … ]
    A2 music:     [ {asset: score.wav, at: 0.0, gain_db: -18, duck_under: A1} ]
    A3 sfx:       [ {asset: touchdown.wav, at: 104.2} ]
  captions: captions.srt

这个结构就是普通数据，所以代理可以像对待任何配置文件一样生成它、做差异、校验它、给它做版本。把时间线当成唯一的事实来源，是代理驱动剪辑的主要架构决定。推断 交换格式用来在工具之间搬时间线：EDL（老、简单）、FCPXML（Final Cut）、AAF/XML（Avid/Premiere），以及开放的 OpenTimelineIO（Academy Software Foundation，Apache-2.0）。已核对

合成：图层、透明通道和遮罩

人工智能改变合成，主要靠分割和抠像：Meta 的 SAM 一族可以从一次点击或一句文字提示，给整段视频里的每个物体做出遮罩；去背景模型不用绿幕就能把人或产品抠出来。生成的影像没有透明通道，所以遮罩是 A 类影像和 B 类叠层之间的桥。实践

精修

色彩

校色让镜头在技术上一致（曝光、白平衡）；调色给它们一种观感。在混合流水线里这比平常更要紧，因为生成的、渲染的和素材库的镜头，各自带着不同的“样子”。所有镜头共用一份 LUT（查找表）或一套调色，再把曝光对齐，是让混合视频看起来像一部片子的最便宜办法。实践 交给网页的成片几乎总是标准动态范围的 Rec.709。实践

稳定

分析帧与帧之间的运动，再反向平移/旋转（FFmpeg 的 vidstab、非线性剪辑里的稳定器）。主要对实拍有用；生成的镜头有时需要反过来（加上一点轻微的摄像机抖动，好接上）。

增强：放大、插值、修复

生成的视频经常是 720p 或 1080p，帧率 24 fps 或更低。神经放大器补上说得通的细节（Real-ESRGAN 一族、SeedVR、Topaz 这类商业工具）；帧插值（RIFE、FILM）合成中间帧，让运动更顺，或做慢动作。两者都是生成式的：它们会编造细节，或把文字涂糊。先做放大和插值，再合成精确叠层，不要反过来。实践

字幕

  • 格式：SRT（纯文本、通用）、WebVTT（网页）、ASS/SSA（带样式，用来烧录“卡拉 OK”式字幕）。
  • 烧录（渲进像素；社交媒体的做法）相对外挂（单独文件；可访问、可搜索、可翻译）。即使也烧进画面，也要交付外挂字幕。实践
  • 时间来自逐词时间戳（第 4 页）。好的字幕遵守行长和阅读速度：大约每行不超过 42 个字符、不超过 2 行，是常见的广播规范。实践

FFmpeg：通用的后端

几乎所有程序化视频工具最后都落到 FFmpeg（截至 2026 年 9 月，当前主版本线是 9.x 已核对）。值得知道它能做什么，即使你从不手写滤镜图——你的代理会写。

FFmpeg 覆盖什么（附极短的示意命令）
工作示意
图像序列 → 视频ffmpeg -framerate 30 -i f_%05d.png -c:v libx264 -pix_fmt yuv420p out.mp4
拼接片段用清单文件的 concat 解复用器，或 concat 滤镜
两段交叉淡化xfade=transition=fade:duration=0.5:offset=6
叠一层透明overlay=x=100:y=50:enable='between(t,12,16)'
烧录字幕subtitles=captions.srt 或 ass=styled.ass
人声底下压低音乐sidechaincompress，用人声做侧链
响度规范化loudnorm=I=-14:TP=-1:LRA=11（要准就跑两遍）
抽出帧来检查fps=1，或用 select='gt(scene,0.3)' 抓场景切换
测量ffprobe（时长、流）、ebur128（响度）、blackdetect、silencedetect、freezedetect

只是示意，不是完整命令。FFmpeg 的滤镜语法很强，但也出了名地容易写错；代理如果每一步之后用 ffprobe 校验输出，就能用得很好。

专业剪辑软件放在哪里

专业非线性剪辑（DaVinci Resolve、Premiere Pro、Final Cut Pro、Avid）适合人工精修那一遍：调色、精细混音、和客户一起看。对代理来说，它们有三种用处：

  1. 当作目的地：代理导出时间线（FCPXML、OTIO、EDL）和媒体，让人类剪辑打开再打磨。这是一种稳的交接方式。推断
  2. 当作可脚本的引擎：Resolve 有 Python/Lua 脚本——但自 Resolve 21.1（2026）起，Python 脚本仅 Studio 版可用（Puget Systems 引用的发行说明原文：“We have moved the ability to script in Python to the Studio version”，即把用 Python 写脚本的能力挪到了 Studio 版；Studio 售价 295 美元）。已核对（Puget Systems，2026-09-10）。Adobe 正把 Premiere 的脚本从 ExtendScript 迁到 UXP；社区报告说新的时间线 API 仍有缺口。未核实的细节。
  3. 经 MCP 桥：社区的 MCP 服务器包住非线性剪辑的脚本 API，代理就能调用“加片段”“渲染”等。有用，但底层脚本 API 的每个限制它都继承。实践

没有 API 的消费级剪辑器（例如 CapCut，截至 2026 年 10 月没有官方剪辑 API）不适合自主代理；对它们做界面自动化很脆弱，也可能违反条款。实践

为什么这一层对代理最要紧

  • 它是确定的：同一条时间线 + 同一批资产 = 同一条视频。
  • 它便宜：重新组装一条两分钟的视频只要几秒到几分钟；重新生成里面的镜头要花钱。
  • 它可测量：时长、响度、黑场、字幕时间都能用代码查。
  • 它能吃掉不完美：提前 0.5 秒切开，能藏住生成的瑕疵；一次叠化能藏住连续性的跳跃。好的剪辑是修补生成影像最便宜的办法。实践
