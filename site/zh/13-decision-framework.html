决策框架：为每个镜头选择方法

人工智能视频导演——人或代理——的核心技能，是把每个镜头路由到对的机器。这一页给出规则、一张取舍矩阵、一个交互助手，以及三套参考技术栈。

试一试：这个镜头用哪种做法？

勾选对一个镜头成立的项。这个助手用本页的路由规则。推断——教学用具，不是神谕。

背后的规则

问题经验法则
生成式视频，还是代码驱动的动画？如果镜头里有任何东西必须精确正确（文字、数据、机制、品牌），用代码 / 渲染。如果它只需要看起来合理、而且好看，生成式视频更便宜。如果两者都要：精确的部分用渲染，其余用生成，再合成（D4），或者给一次渲染换风格（D2）。
什么时候三维渲染更好？物体必须在很多镜头里保持一致；摄像机必须精确移动；机制或物理必须正确；你需要同一场景的很多变体。
什么时候先生成静帧？几乎总是在图生视频之前：静帧便宜，生成和检查都便宜，能修构图和身份，并给图生视频一个精确的起点。
外部接口，还是本地推理？要最好的质量、又不想备硬件，用接口；要隐私、大批量时的成本、确定性的重跑，以及许可允许的开源模型，用本地。按你所在地区核对开源模型许可（有的排除欧盟）。
声音分开生成吗？有口播的多镜头视频要分开（声音一致、用词精确、分轨、字幕）。原生音频适合短的独立片段和环境声。
用专业剪辑软件吗？给人做收尾（调色、混音、客户审阅）——通过时间线交接（FCPXML/OTIO）。不要把它当代理的主引擎，除非它有稳定的脚本接口（Resolve Studio）。
什么容易精确自动化？渲染代码、组装、从时间戳来的时间、字幕、响度、编码、元数据检查、局部重建。
什么仍然是概率的？任何生成式产出（视频、图像、语音的韵律、音乐）、人工智能对质量的判断，以及代理自己的创作选择。
怎样组合才能得到专业结果？确定性的骨架（剧本、时间线、渲染、混音）+ 带参考的生成式插入 + 统一的观感（调色、字体、声音）+ 人的检查点。

参考技术栈：入门 → 高级

给使用编程代理的 Windows 工程师的示意架构——不是万能方案。工具名是某一类的例子；替代品见工具图。

目标：有口播的讲解片和产品视频，大多由代码驱动

  • 代理：Claude Code / Codex / Cursor，加上一套视频技能包（Remotion 技能或 HyperFrames 技能；或 Manim）。
  • 画面：一个代码框架（基于 React/HTML，或 Manim）。少量生成的空镜，走单一接口（例如某个主要模型的 “Fast/Lite” 档）。
  • 声音：一家云端语音合成（或许可合适时用本地开源模型）；词的时间来自厂商，或来自 faster-whisper。
  • 音乐：已获许可的资料库曲目，或带商用条款的音乐接口。
  • 组装：框架的渲染器 + FFmpeg；字幕来自时间戳；两遍响度。
  • 质检：ffprobe、响度、语音识别对照剧本、代理在提示点检查静帧；你看结果。
  • 成本画像：主要是代理 token + 几美分的语音合成 + 几美元的生成空镜。

目标：纪录片风格和营销视频，技术混用

  • 入门里的一切，再加上：
  • 用图像模型加参考图做关键帧；图生视频走聚合器（fal/Replicate/Runway API），外面套你自己的适配器。
  • 三维：用 Python 无界面驱动 Blender（可选经 MCP 服务器）。
  • 把项目当成一次构建：shotlist.json + timeline.json + 带输入哈希的依赖图；异步生成的任务表；成本账。
  • 质检栈：检测器 + 文字识别 + 帧交给视觉模型 + 用能看视频的模型做一遍整片 + 人的关卡。
  • 来源：带许可的资产清单；用 C2PA 给最终导出签名。

目标：电影感、靠角色推动，或大批量制作

  • 进阶里的一切，再加上：
  • 本地或租来的显卡，在 ComfyUI 里跑许可兼容的开源模型（例如 Apache-2.0 的 Wan 2.2，营收门槛内的 LTX-2.5），用来便宜地迭代；用 LoRA 做角色和产品；用控制信号（深度 / 姿态）做 D2 再风格化。
  • 计算机图形加人工智能的混合：精确摄像机的三维粗模 → 视频生视频再风格化；数字人 / 口型同步，并留同意记录。
  • 导演加子代理：并行的镜头搭建者和专门的批评者（连续性、可读性、节奏、品牌），上面有一个协调者。
  • 收尾交接给专业非线性剪辑软件（OTIO/FCPXML）做调色和混音；多格式交付；本地化。
  • 运维：容器化的工具链、钉死的版本、每个密钥的花费上限、监视模型弃用。
