程序化的二维/三维动画与渲染

代码怎样变成会动的画面。这是视频制作里最像普通软件工程的部分，也是编程代理最强的地方。

核心想法：视频是时间的函数

每一种代码驱动的动画工具，从数学讲解库到电影渲染器，实现的都是同一个循环：

for frame in range(duration_seconds * fps):      # e.g. 120 s × 30 fps = 3,600 frames
    t = frame / fps
    scene_state = evaluate_scene(t)               # where is everything at time t?
    image = render(scene_state, camera_at(t))     # turn the state into pixels
    write(image)                                  # PNG sequence or straight to an encoder
encode(frames, audio) -> video.mp4

这一页剩下的，都是 evaluate_scene（场景图、关键帧、模拟）和 render（二维绘制、光栅化、光线追踪）的细节。实践

代理写动画时，最重要的一条规则

第 n 帧的画面必须只取决于 n（以及固定的输入），绝不能取决于墙上时钟、网络时序，或没有种子的随机数。按帧的渲染器会把帧打乱顺序、并行地画；任何靠真实时间或定时器的东西都会闪，或者对不齐。Remotion 的文档为此把一切都建在 useCurrentFrame() 上；HyperFrames 在抓取每一帧之前，先把时间线寻到该帧。已核对（Remotion 基础，HyperFrames README）

场景图：场景是怎样表示的

场景图是一棵节点树。每个节点有相对父节点的变换（位置、旋转、缩放），再加上内容（一个形状、一块网格、文字、一盏灯、一台摄像机）。挪动父节点，子节点就跟着挪——和 DOM，或一棵 React 组件树，完全一样。

关键帧、插值与缓动

你很少去指定每一帧。你设置关键帧——某个属性在某些时刻的值——工具在它们之间插值。缓动曲线决定怎么变：线性运动看起来机械；缓入/缓出看起来自然；弹簧会冲过头，再落定。

时间线把动画编成组：这个序列在第 12 秒开始，持续 4 秒；在它里面，标签于 0.5 秒淡入。网页框架用嵌套的组件或时间线来表达；Python 库用按顺序的 play() 调用；三维套件里则是轨道和条带。

几何、材质、光与着色器（三维）

  • 几何：三角形/多边形的网格、曲线、体积（烟）、点云或高斯泼溅。
  • 材质：多数工具用基于物理的渲染（PBR）——基础色、粗糙度、金属度、法线贴图、自发光。“带着煤烟条痕的拉丝钢助推器”，就是一份材质加上纹理。
  • 灯光：太阳光、面光源、点光源，以及从各个方向照亮场景的环境图（HDRI）。
  • 着色器：算表面颜色的小程序（在二维网页工具里，还包括全屏效果）。常见界面是基于节点的着色器图；它们同样可以写脚本。

渲染：把场景变成像素

光栅化（实时）

把三角形投影到屏幕上，再给每个像素着色。在 GPU 上，一帧只要几毫秒。游戏引擎、浏览器 WebGL、Blender EEVEE。阴影、反射和全局光照是近似的。

路径追踪（离线）

模拟每个像素上的许多条光线在场景里反弹。光在物理上是准确的；采样不多就有噪声；一帧要数秒到数分钟。Blender Cycles，以及电影渲染器。人工智能降噪器能减少所需的采样。

二维矢量渲染

画形状、文字、SVG 和图像，通常借无界面浏览器（网页框架）或 Cairo/OpenGL（Python 库）。快；文字绝对清晰。

成本直觉：两分钟的视频、30 fps，是 3,600 帧。路径追踪若一帧 30 秒，一台机器就是 30 小时——所以制作才会并行渲染、降低采样，或改用实时引擎。二维渲染若一帧 50 毫秒，一共就是 3 分钟。推断（算术）。

物理与程序化运动

有的运动不是编排出来的，而是算出来的：刚体下落、发动机冒出的烟、粒子、布料、流体，或由真实方程给出的轨迹。模拟通常只跑一次，然后烘焙（按帧缓存到磁盘），渲染就可以重复，也可以并行。种子让“随机”的粒子系统变成确定的。做工程讲解时，着陆助推器的轨迹可以来自 Python 里一份真正的物理模型，再作为关键帧送进三维场景——画面于是按构造就是对的，这是神经视频模型给不了的保证。推断

从图像到视频文件

  1. 渲染帧，成为图像序列（PNG；高动态范围用 EXR），或直接送进编码器。
  2. 编码，用某种编解码器（要兼容用 H.264，要效率用 H.265/AV1，剪辑母版用 ProRes），固定帧率，通常经过 FFmpeg。
  3. 封装音频轨道进容器（MP4/MOV/MKV）。

图像序列对自动化更友好：在第 2,100 帧崩溃，就从第 2,100 帧接着来；代理可以修好一个镜头，只重渲它的帧范围。实践

三类代码驱动的工具，看一眼

写一个外观取决于帧号的网页或 React 组件；无界面的 Chromium 寻到每一帧、截下来，再由 FFmpeg 编码。整个网页平台都在：CSS、SVG、字体、Canvas、WebGL（Three.js）、动画库、图表。

代表工具（2026 年 10 月）：Remotion（React；GitHub 星标约 64.7k；源码可得的许可，个人以及不超过 3 人的公司免费，再往上要付费），HeyGen 的 HyperFrames（普通 HTML 加数据属性，Apache-2.0，2026 年 3 月以来星标约 65.7k，明确“为代理而建”，并附带代理技能），Motion Canvas / Revideo（TypeScript 生成器；Motion Canvas 自 2024 年 12 月起没有再发版）。星标数来自 2026-10-17 的 GitHub API。已核对

对编程代理来说的长处与限度

代理擅长代理吃力
编写和重构场景代码；把场景参数化（数据 → 动画）口味：间距、节奏、色彩是否和谐、“这看起来够不够高级？”
精确的版式、字体，以及卡上口播时间戳的时机从零做出好的三维资产（建模、画纹理）
在选定的帧上渲染静帧，用来检查自己的工作灯光和材质要看得出照片级
改完之后，对单个镜头做确定的重渲没有视觉反馈时的三维空间推理（取景、遮挡）
物理和数据的正确性（它们算得出来）角色动画和表演
