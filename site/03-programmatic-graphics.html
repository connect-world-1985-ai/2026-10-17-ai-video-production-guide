Programmatic 2D/3D animation and rendering

How code becomes moving pictures. This is the part of video production that behaves most like normal software engineering, and where coding agents are strongest.

The core idea: a video is a function of time

Every code-driven animation tool, from a math-explainer library to a film renderer, implements the same loop:

for frame in range(duration_seconds * fps):      # e.g. 120 s × 30 fps = 3,600 frames
    t = frame / fps
    scene_state = evaluate_scene(t)               # where is everything at time t?
    image = render(scene_state, camera_at(t))     # turn the state into pixels
    write(image)                                  # PNG sequence or straight to an encoder
encode(frames, audio) -> video.mp4

Everything else on this page is detail about evaluate_scene (scene graphs, keyframes, simulation) and render (2D drawing, rasterisation, ray tracing). Practice

The single most important rule for agent-written animation

The picture at frame n must depend only on n (and fixed inputs), never on wall-clock time, network timing or random numbers without a seed. Frame-based renderers render frames out of order and in parallel; anything time- or timer-based will flicker or desync. Remotion's documentation builds everything around useCurrentFrame() for this reason; HyperFrames seeks a timeline to each frame before capture. Verified (Remotion fundamentals, HyperFrames README)

Scene graphs: how a scene is represented

A scene graph is a tree of nodes. Each node has a transform (position, rotation, scale) relative to its parent, plus content (a shape, a mesh, text, a light, a camera). Moving a parent moves its children — exactly like the DOM, or a React component tree.

Keyframes, interpolation and easing

You rarely specify every frame. You set keyframes — the value of a property at certain times — and the tool interpolates between them. The easing curve decides how: linear motion looks mechanical; ease-in/ease-out looks natural; springs overshoot and settle.

Timelines group animations: this sequence starts at second 12 and lasts 4 seconds; inside it, the label fades in at 0.5 s. Web frameworks express this as nested components or timelines; Python libraries as ordered play() calls; 3D suites as tracks and strips.

Geometry, materials, light and shaders (3D)

  • Geometry: meshes of triangles/polygons, curves, volumes (smoke), point clouds or Gaussian splats.
  • Materials: most tools use physically based rendering (PBR) — base colour, roughness, metallic, normal maps, emission. A "brushed steel booster with soot streaks" is a material plus textures.
  • Lights: sun, area, point lights and environment (HDRI) images that light the scene from all directions.
  • Shaders: small programs that compute surface colour (and in 2D web tools, full-screen effects). Node-based shader graphs are the common UI; they are also scriptable.

Rendering: turning the scene into pixels

Rasterisation (real-time)

Project triangles to the screen, shade each pixel. Milliseconds per frame on a GPU. Game engines, browser WebGL, Blender EEVEE. Approximates shadows, reflections, global illumination.

Path tracing (offline)

Simulate many light rays per pixel bouncing through the scene. Physically accurate light; noisy unless many samples; seconds to minutes per frame. Blender Cycles, film renderers. AI denoisers cut the samples needed.

2D vector rendering

Draw shapes, text, SVG and images, typically via a headless browser (web frameworks) or Cairo/OpenGL (Python libraries). Fast; perfectly sharp text.

Cost intuition: a 2-minute video at 30 fps is 3,600 frames. At 30 s/frame of path tracing that is 30 hours on one machine — which is why productions render in parallel, render at lower samples, or use real-time engines. At 50 ms/frame of 2D rendering it is 3 minutes. Inference (arithmetic).

Physics and procedural motion

Some motion is not authored but computed: rigid bodies falling, smoke from an engine, particles, cloth, fluids, or a trajectory from real equations. Simulations are usually run once and baked (cached to disk per frame) so rendering is repeatable and parallelisable. Seeds make "random" particle systems deterministic. For an engineering explainer, the trajectory of a landing booster can come from an actual physics model in Python and be fed into the 3D scene as keyframes — the picture is then correct by construction, something a neural video model cannot guarantee. Inference

From images to a video file

  1. Render frames as an image sequence (PNG, or EXR for high dynamic range) or stream them directly into an encoder.
  2. Encode with a codec (H.264 for compatibility, H.265/AV1 for efficiency, ProRes for editing masters) at a fixed frame rate, usually via FFmpeg.
  3. Mux audio tracks into the container (MP4/MOV/MKV).

Image sequences are friendlier to automation: a crash at frame 2,100 resumes at 2,100, and an agent can fix one shot and re-render only its frame range. Practice

Three families of code-driven tools, in one glance

Write a web page or React component whose appearance depends on the frame number; a headless Chromium seeks to each frame, screenshots it, and FFmpeg encodes. You get the entire web platform: CSS, SVG, fonts, Canvas, WebGL (Three.js), animation libraries, charts.

Representative tools (Oct 2026): Remotion (React; ~64.7k GitHub stars; source-available licence, free for individuals and companies up to 3 people, paid above), HyperFrames by HeyGen (plain HTML + data attributes, Apache-2.0, ~65.7k stars since March 2026, explicitly "built for agents" with bundled agent skills), Motion Canvas / Revideo (TypeScript generators; Motion Canvas has had no release since Dec 2024). Full 3D applications with Python APIs or command-line rendering. Blender (free, GPL; 5.2.2 LTS released 2026-09-15) is the default for agents because it runs headless (blender -b scene.blend -P script.py) and everything is reachable from Python. Real-time engines (Unreal, Unity, Godot) render fast and have big asset ecosystems, but are heavier to automate. Web 3D (Three.js, ~116k stars) can be rendered through the web-based frameworks above.
