How a coding agent becomes a video director

The demos that look like "an AI made a whole film" are, underneath, a planner writing structured files, a programmer calling tools, and a critic reading back frames, transcripts and numbers. This page takes that apart: planning, technology choice, orchestration, self-inspection, revision, and multi-agent setups — with what the evidence actually supports.

The architecture in one diagram

1 · Creative planning: from a sentence to a production plan

The agent's first job is to turn a vague request into structured, checkable artefacts. A good plan is mostly data:

ArtefactContentHow reliable is an LLM at it?
Creative brief / objectivesAudience, tone, length, platform, key messages, must-havesGood, if it asks or states assumptions Practice
Research notesFacts with sourcesGood with web search and citations; unreliable from memory (hallucinated numbers) Practice
Script / narrationWords, timed at ~130–160 wpmStrong — this is core LLM competence; still needs fact-check and a human ear
StoryboardOne frame description (or generated still) per shotDescriptions good; spatial composition and visual taste weaker
Shot listPer shot: duration, type, technology, camera, assets, audio cuesStrong as structure; durations must later be measured from audio
Style biblePalette, fonts, look, references, camera grammar, sound paletteMedium; generic unless given references
Acceptance criteriaTestable checks: "no text artefacts", "−14 LUFS ±1", "all facts sourced"Strong — and the key to later self-evaluation
Schedule & budgetOrder of jobs, parallelism, API cost estimateGood for structure; cost estimates need real price tables
What a machine-readable shot looks like

  "id": "S07",
  "beat": "Entry burn slows the booster",
  "narration_ref": "seg_05",           // duration comes from the measured audio

Illustrative structure (not a standard). Keeping status, version and an input hash per shot is what makes resuming and partial re-rendering possible. Inference

2 · Technology selection per shot

Different shots in the same video can — and usually should — use different technologies. A routing table the agent can apply:

If the shot needs…Route toWhy
Exact text, numbers, equations, charts, UIB 2D codeOnly rendering guarantees correctness
Physically/technically accurate motion (trajectories, mechanisms)B 3D + simulationCorrect by construction
Photoreal atmosphere, nature, crowds, "cinematic" b-rollA generative video (I2V from a checked keyframe)Cheapest route to realism
A real event, real product, real personC licensed footage / screen captureTruthfulness and rights
A presenterA4 avatar (with consent) or recorded human—
Something cheap and calm under narrationC1 still + slow pan, or parallaxLow cost, full control
Realistic look + exact motionD2 3D blockout → video-to-videoCombines B's control with A's look

Keeping mixed shots consistent is a design task: one palette and type system for all overlays; one colour grade/LUT across every shot; reference images (character sheets, product photos) passed to every generative call; the same lens/camera grammar in 3D and in prompts; a single music bed and room tone that glue cuts together. Three levels of autonomy

Direct tool use

The agent runs commands one by one in conversation. Fast to start, hard to reproduce: the "pipeline" exists only in the chat history.

Scripted workflow

The agent writes the pipeline as code (a build script / DAG with cached steps) and runs it. Reproducible and resumable; changes are code diffs.

Autonomous loop

The agent runs the pipeline, inspects outputs, and edits plan or code without asking — within a budget and with approval gates.

The robust combination is "scripted workflow + autonomous loop around it": the agent uses its judgement to edit the plan and code, but every production run is a reproducible build. That mirrors how good software teams use CI. Inference

4 · Autonomous quality inspection: how an agent "watches" its video

Current coding agents mostly cannot watch a video the way you do. Claude's documented API input is images (no video), and Gemini's API accepts video but samples it at 1 frame per second by default. What current AI judges genuinely fail to notice
  • Temporal order and fine motion. On the TOMATO benchmark, humans scored 95.2% while the best model scored 37.9%; shuffling frames barely hurt models (37.8% → 28.5%), suggesting they lean on single frames. Verified (arXiv 2410.23266, 2024-era models). Vinoground found ~90% human vs ~50% GPT-4o on temporal counterfactuals (arXiv 2410.02763).
  • Anything between samples: single-frame glitches, flicker, brief morphing.
  • Lip-sync drift of a few frames, A/V offset, rhythm and pacing that "feel off".
  • Physics plausibility beyond obvious failures.
  • Its own blind spots: a judge model scoring output produced with help from the same model family can be biased; Code2Video uses Gemini 2.5 Pro as both in-loop critic and evaluation judge. Inference

Encouragingly, judges that see the rendered output do much better than those that only read code: one study reports 87.8% agreement with humans for a VLM judge viewing rendered video vs 69.1% for a text-only judge (SimuScene, arXiv 2602.10840, appendix). Verified

A practical inspection stack, cheapest first: probes → detectors → ASR/OCR → targeted frames to a vision model → one whole-video pass → human. Each layer only runs if the previous passed. Inference

5 · Iterative improvement: from critique to concrete change

The hard step is translating "this looks wrong" into an edit. Two kinds of fixes behave completely differently:

ProblemConcrete modificationKind
Camera move too fastExtend keyframe span 2 s → 3.5 s; ease-in-out curveDeterministic B
Scene too darkRaise key light / exposure; or grade +0.5 stop in postDeterministic
Label overlaps the boosterMove overlay anchor; re-composite only V2 layerDeterministic
Narration too early for the visualShift segment start; or retime animation to the word timestampDeterministic
Music too loud under speechDuck −6 dB in speech regions; re-mix only audioDeterministic
Weak transitionSwap cut type (dissolve → match cut); adjust durationDeterministic
Generated shot has a melting hand / wrong logoRe-generate with new seed, tighter prompt, or I2V from a corrected still; or cut shorterProbabilistic A
Character looks different from shot 3Re-generate with reference images / LoRA; or replace with rendered shotProbabilistic
Composition of generated shot weakDesign the start frame as a still first, then I2VPartly deterministic
Continuity break between shotsChain last frame → first frame; insert a cutaway; reorderMixed

Re-render only what changed. Treat the production like a build system: each shot's output is a function of its inputs (code, parameters, assets, model version, seed). Hash the inputs; if the hash didn't change, reuse the cached output. Narration change → only affected shots and the audio mix rebuild. This is the same idea as make or Bazel, applied to media. Inference

Knowing when to stop

  • All acceptance criteria pass (the reason to write testable criteria up front).
  • Iteration cap per shot — video-use caps self-evaluation at 3 passes; after that, escalate to the human. Verified (video-use SKILL.md)
  • Budget cap in money and time, tracked in a cost ledger.
  • Diminishing returns: the critic's issues are now matters of taste, or contradict earlier critiques (oscillation).
  • Human gate: the agent presents the cut with a list of known compromises. Practice

6 · Multi-agent production: what the evidence says

Role-play crews (scriptwriter, director, animator, editor, QA…) are popular in research and marketing. What is actually supported:

EvidenceFindingStrength
FilmAgent (arXiv 2501.12909)Multi-agent crew in virtual 3D scored 3.98 vs 3.04 for a single agent (human ratings)Weak–moderate: 15 story ideas, small rater pool
Code2Video (arXiv 2510.01174)Planner + coder + critic pipeline: aesthetics/quiz 87.9/86.0 vs 37.8/40.0 for direct code generation (Claude Opus 4.1). Removing the planner hurt most; removing the critic hurt lessModerate: shows decomposition matters; judge is an LLM
TheoremExplainAgent (arXiv 2502.19400)Full-video success varied hugely by model (o3-mini 93.8% vs Claude 3.5 Sonnet 2.1%); main failures were code hallucinations and layout overlapsModerate; 2025-era models
General agent research (Kim et al., Cemri et al.)Multi-agent helps parallelisable tasks and hurts sequential ones; multi-agent frameworks show high failure rates from coordination problemsStrong, but not video-specific
Recommendation

One strong director agent owns the plan and the project files; it dispatches specialist subagents for work that is parallel and well-specified (render shot 4, write animation 7, critique pacing, critique legibility), each with a narrow brief and the style bible. Avoid committees of peer agents debating creative choices. Practitioner repos follow this pattern (video-use: parallel animation sub-agents; product-launch-video: four parallel critics). Inference supported by the evidence above.

How agents share state

  • Files, not chat: brief, script, shot list, style bible, timeline, manifest, decision log — all in a project folder under version control. Media binaries in a content-addressed store or Git LFS. Practice (video-use keeps project.md, edl.json, cached transcripts, a verify/ folder)
  • Contracts between agents: a subagent receives a shot spec + style bible and must return a file at a known path plus a short report.
  • One writer per file: the director merges; subagents propose.

How close are agents to being autonomous directors?

Today, reliably

Planning documents, scripts with sourced facts, code-driven animation, assembly, captions, mixing to spec, objective QA, partial re-renders, keeping a reproducible project.

Today, with supervision

Choosing generative shots, judging visual quality from frames, iterating style, routing shots across technologies, editing real footage (with plan approval).

Not yet

Consistent taste over a whole film, reliable temporal judgement, long-form character consistency without human curation, knowing when "good enough" is good enough for your audience.
