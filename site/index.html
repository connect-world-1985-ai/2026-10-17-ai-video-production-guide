How AI-assisted videos are actually made

A field guide for a software engineer who wants to direct video production with coding agents. Vendor-neutral, evidence-labelled, written in October 2026.

The one-paragraph answer

There is no single "AI video" technology. A finished video is almost always assembled on a timeline from shots and sounds that came from very different machines: some shots are imagined pixel by pixel by a neural network, some are computed by a renderer from a scene described in code, some are real footage or stills, and the voice, music and effects come from separate audio models. A coding agent turns into a "director" when it writes the plan as data, picks the right machine for each shot, calls those machines through code, CLIs and APIs, then watches its own output (frames, transcripts, loudness numbers) and edits the plan until the result matches the brief. The reliable parts of that loop are the deterministic ones (code, rendering, assembly, measurement). The unreliable parts are the generative samples and the agent's own taste.

The mental model in four pictures

1. Four ways to get pixels

Every frame on screen was produced by one of four mechanisms. Learning to tell them apart is the most important skill in this whole field, because each one has a different cost, controllability and failure pattern.

A Neural synthesis

A trained model imagines pixels from a text prompt, an image or another video. Nothing is "modelled": there are no objects, only learned statistics of how the world looks and moves.

Feels like: sampling from an LLM. Beautiful, fast to start, hard to control exactly, never quite the same twice.

B Rendered scene

Code describes a scene (shapes, text, 3D meshes, lights, a camera, keyframes over time). A renderer computes each frame deterministically.

Feels like: compiled software. Exact, diffable, repeatable, but you have to build everything you show.

C Assembly

A timeline places existing media (clips, images, voice, music, captions) in time and composites them into the final video.

Feels like: a linker/build step. Mostly deterministic; quality depends on the parts.

D Hybrid

Real productions mix all three: a rendered diagram here, a generated cinematic shot there, a narrated timeline over all of it, sometimes AI re-styling a rendered pass.

Feels like: a micro-service system with a build pipeline.

Real footage (filmed or stock) is a fifth source that enters through C, and AI can also edit real footage (cut it, caption it, relight it, restyle it) — see the taxonomy.

4. Where the agent sits

A coding agent (Claude Code, Codex, Cursor, Gemini CLI…) does not "see" or "draw" video by itself. It is a planner and programmer that can:

  • write scene code (a React/Remotion composition, a Manim scene, a Blender Python script, an FFmpeg filter graph);
  • call tools: CLIs, SDKs, cloud model APIs, MCP servers;
  • read results back in a form it can reason about: still frames as images, transcripts as text, measurements as numbers, or whole clips via a video-capable model;
  • keep state in files: the plan, the shot list, asset manifest, decisions, costs.

Everything "magical" in agent video demos reduces to those four abilities plus good tools. Inference

Three things engineers usually get wrong at first

  1. "The best model will make my whole video." Text-to-video models produce short clips (typically single-digit to tens of seconds per generation as of 2026) with limited control over exact text, numbers, diagrams and continuity. Explanatory and technical videos are mostly B + C, with A for atmosphere. Practice
  2. "The agent can watch the video like I do." Most agents inspect sampled frames and text side-channels. Models that accept real video exist, but they sample at low frame rates and miss fast or subtle problems (flicker, a one-frame glitch, lip-sync drift). Measurement code catches what eyes-by-proxy miss. Practice
  3. "Audio is an afterthought." Viewers forgive imperfect pictures far more than bad sound. Narration usually drives the timing of the whole edit: you generate the voice first, read its word timestamps, and cut the pictures to it. Practice
