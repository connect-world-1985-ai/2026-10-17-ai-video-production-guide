Page 8 · §8 — Complete production lifecycle

Worked example: a 2-minute documentary on how a booster lands

The request: "Produce a professional two-minute documentary-style video explaining how a reusable launch vehicle returns from space and lands vertically. Include animated 3D sequences, technical diagrams, cinematic scenes, realistic sound effects, professional English narration, background music, and accurate subtitles." Here is how a coding agent could execute it end to end — and where it would need you.

The key design decision, made up front

"Accurate" + "technical diagrams" + "how it works" means the backbone must be rendered (B), because only rendering guarantees correct trajectories, labels and numbers. Generative video (A) is used for atmosphere — the cold open, ocean at dusk, a wide establishing shot — where plausibility is enough. Real archive footage (C) is the most credible proof shot, if licences allow. Narration drives timing. Inference

How the intermediate assets fit together

The 16 steps

1 · Research and fact-checking
Objective
A sourced fact sheet: flight phases (separation, flip, boostback, entry burn, aerodynamic descent with grid fins, landing burn, legs), approximate altitudes/speeds, why reuse lowers cost — with every number linked to a source.
Tools
Web search + fetch; agency and manufacturer publications; papers. Optional second model as a fact-check reviewer.
Agent does
Collect, cite, flag disagreements between sources, mark any number without a primary source.
In → out
brief.md → research/facts.md with links.
Automatable
Mostly. Needs judgement: which simplifications are acceptable for a general audience.
Failure modes
Hallucinated numbers; mixing up different vehicles; outdated facts. Mitigation: no number enters the script without a link. Practice
2 · Script development
Objective
≈ 260–300 words of narration (2 min at ~140 wpm with pauses), documentary tone, one idea per beat.
Agent does
Draft, read-aloud timing estimate, pronunciation lexicon (e.g. acronyms), cite each claim to the fact sheet.
In → out
facts.md → script.md (segments seg_01…seg_12), lexicon.yml.
Creative judgement
Voice and story arc: hook, tension ("only seconds of fuel"), payoff. Human approval checkpoint #1.
Failure modes
Too dense for 2 min; generic phrasing; claims drifting from sources.
3 · Storyboarding
Objective
One frame per shot that fixes composition and look.
Tools
Image generation for atmospheric frames; quick 3D/2D renders for technical frames; a contact sheet.
Agent does
Generate/render stills, assemble a storyboard sheet, check them as images (cheap to inspect).
Failure modes
Inconsistent vehicle design between stills → fix by creating one reference model/sheet first.
4 · Shot planning
Objective
shotlist.json: per shot technology, camera, assets, overlays, SFX cues, acceptance criteria (see page 7 for the format).
Automatable
Yes; durations are placeholders until narration is measured (step 9).
5 · Asset generation and acquisition
Objective
Vehicle 3D model, environment maps, textures, fonts, archive clip, SFX library sounds, reference images.
Tools
Free asset libraries (e.g. Poly Haven), 3D-generation services, licensed stock; agency media libraries.
Agent does
Fetch, record licence + source per asset in a manifest.
Failure modes
Unclear licences. NASA imagery is generally not copyrighted but its logos and insignia are restricted; ESA and company media have their own terms — check each item (page 12). Practice
6 · Selecting technology per shot

Apply the routing table (page 7): technical truth → render; atmosphere → generate from a designed keyframe; proof → archive. The agent writes the decision and reason into decisions.log so a human can veto it.

7 · 3D and motion-graphics production
Tools
Blender via Python (headless) for S04/S06/S07/S10; a code-driven 2D framework (React/HTML-based or Manim) for S02/S03/S05/S09; a small Python physics model for the trajectory and landing-burn curves.
Agent does
Write scene scripts parameterised by shot spec; render low-res previews; check stills at key frames; final render as image sequences with alpha where overlays are needed.
Creative judgement
Lighting and materials (the "premium" look) — the weakest area for agents. Use a pre-made look-dev scene/HDRI from the style bible.
Failure modes
Camera clipping into geometry, label overlaps, wrong scale, long render times. Mitigation: preview renders at 25% resolution, check frames, then full quality.
8 · Generative video where appropriate
Tools
An image model for keyframes; an I2V model via API (first frame, optionally last frame, reference images).
Agent does
Generate 2–4 candidates per shot, inspect frames, select, log seed/model/version/prompt/cost.
Failure modes
Physically wrong plume direction, extra engines, morphing logos, cost overrun. Mitigation: no technical claims in generated shots; cut them short; strict per-shot budget.
9 · Narration generation
Tools
A TTS API or local model; ASR or forced alignment for word timings.
Agent does
Synthesise per segment, apply the lexicon, measure durations, extract word timestamps, run ASR and diff against the script.
Creative judgement
Voice choice and delivery. Human approval checkpoint #2 (listen to one minute).
Failure modes
Mispronounced terms; unnatural emphasis; skipped words.
10 · Music and sound effects
Tools
Music generation API with commercial terms, or a licensed library track fitted to 2:00; SFX generation or library (engine roar, sonic boom, wind, metal clunk of legs, touchdown).
Agent does
Request music with exact duration and a build toward the landing; place SFX at word/event cue points.
Failure modes
Music competing with narration; unrealistic or cartoonish SFX; licence terms on free tiers.
11 · Editing and composition

Generate timeline.json from the shot list and measured narration; composite overlays (labels, arrows) on rendered or generated plates; apply one colour grade to all shots; transitions mostly hard cuts and a few dissolves. Practice

12 · Synchronisation

Shot boundaries snap to narration segment boundaries (plus breath pads); animation events (legs deploy, burn start) start on the relevant word; SFX on the event frame; music hits (if any) aligned to the touchdown. Everything is driven by timestamps, so re-recording narration re-times automatically.

13 · Rendering

Assemble with FFmpeg or the code framework's renderer: preview at 720p fast, final at 1080p or 4K. Loudness-normalise the mix (two-pass), mux, export captions.

14 · Automated quality assurance
  • Probes: 2:00 ±2 s, 1080p, fps constant, audio 48 kHz stereo.
  • Detectors: no black/frozen frames, no silence gaps > 1.5 s outside intended pauses; integrated loudness at target; true peak ≤ −1 dBTP.
  • ASR of final mix vs script: word error rate ≈ 0 for narration; captions match.
  • OCR on overlay frames: all labels spelled correctly.
  • Vision checks on frames at every cut ±0.5 s and every cue point: correct objects, no overlap, consistent vehicle design, style match.
  • One whole-video pass with a video-capable model against the brief and acceptance criteria.
  • Fact audit: every on-screen number and narration claim maps to a source.
15 · Revision cycles

Issues are mapped to the smallest change (see the table on page 7) and only affected shots are rebuilt. Typical: 2–3 automated cycles, then human review checkpoint #3 on the full cut; human notes become shot-level change requests.

16 · Final encoding and delivery

Master (high-bitrate or ProRes), YouTube upload (H.264 MP4, AAC 48 kHz, per platform spec), optional 9:16 cut-down, SRT/VTT captions, a credits/sources file, an asset licence manifest, and provenance metadata (C2PA) applied to the final export — re-encoding strips earlier manifests. Practice

Resuming, revising, reproducing

  • Everything is a file in a repo: plan, code, timeline, manifests, decision log. Media in a content-addressed store (or Git LFS) referenced by hash.
  • Each shot has a status and an input hash; a build script skips shots whose inputs are unchanged. "Resume" means re-running the build.
  • Generative shots are pinned: once accepted, the clip file itself is the source of truth (model versions change; re-generation is not reproduction).
  • Revisions are diffs: "make the entry burn longer" changes S07's duration in shotlist.json and a narration segment; the build rebuilds S07, the timeline, captions and mix.
  • Another agent can take over by reading the brief, decisions log and shot statuses — the same idea as the tracker and memory file behind this guide. Inference
