Editing, compositing, finishing and encoding

Post-production is where separately made shots and sounds become one video. For an agent, it is also the most deterministic and automatable part of the whole pipeline.

Four jobs that people lump together as "editing"

Editing (the cut)

Which shot, in which order, for how long, with which transition. Storytelling and rhythm.

Compositing

Stacking layers within a shot: text over footage, a diagram over a render, a keyed presenter over a background.

Finishing

Colour grading, stabilisation, upscaling, frame-rate conversion, denoise, captions, final mix.

Encoding & delivery

Compressing into a codec and container for each target (YouTube, social 9:16, archive master), with captions and metadata.

The timeline as a data structure

Every editor — Premiere, Resolve, Final Cut, a JSON video API, an FFmpeg command — represents the same thing:

timeline:
  fps: 30, resolution: 1920x1080, duration: 120.0
  video_tracks:
    V1: [ {asset: shot01.mp4, in: 0.0, out: 6.5, at: 0.0, transition_in: none},
          {asset: shot02_render.mov, in: 0.0, out: 9.0, at: 6.5, transition_in: {xfade, 0.5s}} … ]
    V2: [ {asset: label_altitude.mov (alpha), at: 12.0, out: 4.0} … ]
  audio_tracks:
    A1 narration: [ {asset: vo_seg01.wav, at: 0.4}, … ]
    A2 music:     [ {asset: score.wav, at: 0.0, gain_db: -18, duck_under: A1} ]
    A3 sfx:       [ {asset: touchdown.wav, at: 104.2} ]
  captions: captions.srt

That structure is plain data, so an agent can generate, diff, validate and version it like any config file. Making the timeline the single source of truth is the main architectural decision for agent-driven editing. Inference Interchange formats exist to move timelines between tools: EDL (old, simple), FCPXML (Final Cut), AAF/XML (Avid/Premiere), and the open OpenTimelineIO (Academy Software Foundation, Apache-2.0). Compositing: layers, alpha and mattes

AI has changed compositing mostly through segmentation and matting: models like Meta's SAM family produce per-object masks across a video from a click or a text prompt; background-removal models cut people or products out without a green screen. Generated footage has no alpha channel, so mattes are the bridge between A footage and B overlays. Practice

Finishing

Colour

Colour correction makes shots technically consistent (exposure, white balance); grading gives them a look. In mixed pipelines this matters more than usual, because generated, rendered and stock shots each arrive with a different "look". A shared LUT (look-up table) or grade applied to all shots, plus matched exposure, is the cheapest way to make a hybrid video feel like one film. Practice Delivery for the web is almost always SDR Rec.709. Practice

Stabilisation

Analyse motion between frames and counter-shift/rotate (FFmpeg vidstab, NLE stabilisers). Mostly relevant for captured footage; generated shots sometimes need the opposite (adding subtle camera shake to match).

Enhancement: upscaling, interpolation, restoration

Generated video often comes out at 720p or 1080p and 24 fps or lower. Neural upscalers add plausible detail (Real-ESRGAN family, SeedVR, commercial tools like Topaz); frame interpolation (RIFE, FILM) synthesises in-between frames for smoother motion or slow motion. Both are generative: they can invent detail or smear text. Apply them before compositing exact overlays, not after. Practice

Captions and subtitles

  • Formats: SRT (plain, universal), WebVTT (web), ASS/SSA (styled, for burned-in "karaoke" captions).
  • Burned-in (rendered into pixels; social media style) vs sidecar (separate file; accessible, searchable, translatable). Deliver sidecar captions even when you also burn them in. Practice
  • Timing comes from word timestamps (page 4). Good captions follow line-length and reading-speed rules (roughly ≤ 42 characters per line and ≤ 2 lines is a common broadcast guideline). Practice

FFmpeg: the universal back end

Almost every programmatic video tool ends in FFmpeg (current major release line 9.x as of Sept 2026 Verified). It is worth knowing what it can do, even if you never write a filter graph by hand — your agent will.

Illustrative only — not complete commands. FFmpeg's filter syntax is powerful but notoriously error-prone; agents do well with it when they validate output with ffprobe after each step.

Where professional editing applications fit

A professional NLE (DaVinci Resolve, Premiere Pro, Final Cut Pro, Avid) is the right tool for a human finishing pass: grading, fine audio mixing, reviewing with a client. For an agent, they matter in three ways:

  1. As a destination: the agent exports a timeline (FCPXML, OTIO, EDL) plus media so a human editor can open and polish it. This is a robust hand-off pattern. Inference
  2. As a scripted engine: Resolve has Python/Lua scripting — but since Resolve 21.1 (2026), Python scripting is Studio-only (release note quoted by Puget Systems: "We have moved the ability to script in Python to the Studio version"; Studio costs US$295). Verified (Puget Systems, 2026-09-10). Adobe is moving Premiere scripting from ExtendScript to UXP; community reports say the new timeline API still has gaps. Unverified detail.
  3. Via MCP bridges: community MCP servers wrap NLE scripting APIs so an agent can call "add clip", "render" etc. Useful, but they inherit every limitation of the underlying scripting API. Practice

Consumer editors without APIs (e.g. CapCut, which has no official editing API as of Oct 2026) are poor targets for autonomous agents; UI automation of them is fragile and may violate terms. Practice

Why this layer matters most for an agent

  • It is deterministic: same timeline + same assets = same video.
  • It is cheap: re-assembling a 2-minute video takes seconds to minutes; regenerating its shots costs money.
  • It is measurable: durations, loudness, black frames, caption timing can all be checked by code.
  • It absorbs imperfection: a cut 0.5 s earlier hides a generated artefact; a crossfade hides a continuity jump. Good editing is the cheapest quality fix for generative footage. Practice
