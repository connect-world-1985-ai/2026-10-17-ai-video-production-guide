Taxonomy: the different ways a video gets made

"AI-generated video" names at least a dozen different mechanisms. This page classifies them by where the pixels come from and where the motion comes from, which are the two questions that predict cost, control and failure.

The two questions that classify any shot

Where do the pixels come from?

Synthesised by a neural network · Rendered from a scene description · Captured by a camera or screen · Composited from other media.

Where does the motion come from?

Learned (the model predicts plausible motion) · Authored (keyframes, code, curves) · Simulated (physics, particles) · Captured (camera, mocap) · Edit-time (cuts, pans, zooms over stills).

Most of the confusion in this field disappears once you ask both questions of every shot. A "3D-looking" product spin can be learned motion over synthesised pixels (a video model) or authored motion over rendered pixels (Blender) — they look similar in a thumbnail and behave completely differently when you need to change the logo colour. Engineer's analogy

A is like asking an LLM for code: fast, often impressive, sometimes subtly wrong, and you validate it. B is like writing the code yourself: slower to start, exact, reviewable, reproducible. C is the build system and linker. D is a system where you keep the parts that must be correct (labels, numbers, logos, timing) in authored code and let generative models fill in the parts that only need to be plausible and beautiful.

Every category in detail

Each block answers the same eight questions from the brief: mechanism, source of pixels, motion, control, consistency, audio, strengths/limits, agent integration.

A — Neural synthesis

A1 Text-to-video (T2V)
Mechanism
A video diffusion (or flow-matching) transformer starts from noise in a compressed "latent" video space and iteratively denoises it, guided by an embedding of your prompt. A decoder turns the latent back into frames. (Details: page 2.)
Pixels
Synthesised.
Motion
Learned. The model generates all frames of the clip together (not one after another, in most current designs), so motion is whatever the training data makes plausible.
Control
Prompt wording, negative prompts on some models, camera-movement vocabulary ("slow dolly in", "aerial tracking shot"), aspect ratio, duration, seed. Low precision: you describe, you don't specify.
Consistency
Within a clip: good for a few seconds, degrades with length. Across clips: poor without references — the same "red rocket" prompt gives different rockets.
Audio
Several 2025-26 models generate synchronised audio natively (dialogue, ambience, effects). Others are silent and audio is added later.
Strong at
Atmosphere, nature, crowds, cinematic b-roll, stylised scenes, "impossible camera" shots.
Weak at
Exact text and numbers, technical correctness (a landing burn that obeys physics), precise choreography, long continuous takes, brand-exact objects.
Agent fit
Good: asynchronous REST APIs (submit → poll/webhook → download). Cost and randomness must be budgeted.
A2 Image-to-video (I2V), first/last frame, reference-to-video
Mechanism
Same model family as T2V, but additionally conditioned on one or more images: a start frame (the clip begins exactly there), optional end frame (the model interpolates a plausible path between), or "reference" images of a character/product that should appear.
Pixels
Synthesised, anchored to your image(s).
Motion
Learned, constrained by start/end states and the prompt.
Control
Much better than T2V: composition, colours, character design and layout are fixed by the image you supply (which you can generate, render, photograph or design precisely).
Consistency
The main industry technique for cross-shot consistency: design keyframes first (consistent), then animate each. Practice
Audio
As T2V.
Strong at
Storyboard-driven productions, product shots from a real photo, animating illustrations, chaining shots (last frame of shot N → first frame of N+1).
Weak at
Large viewpoint changes (model must invent unseen sides), fine text in the image may warp as it moves.
Agent fit
Excellent: the agent can generate or render the keyframe deterministically, check it as a still (cheap to inspect), then spend money on animation.
A3 Video-to-video and generative editing
Mechanism
The model is conditioned on an input video (or signals extracted from it: depth, edges, pose, optical flow, segmentation masks) and asked to re-generate it with changes: new style, new lighting, replaced object, extended duration, removed element, changed camera angle.
Pixels
Synthesised, structurally guided by the source.
Motion
Mostly inherited from the source video. This is the key benefit: you author or capture motion, the model supplies appearance.
Control
Medium–high: structure from the source, look from prompt/reference.
Consistency
Good within the clip; style can still drift between separately processed clips.
Audio
Usually kept from the source or added later.
Strong at
Turning a rough 3D blockout into a cinematic shot (see D2), relighting, restyling, object removal, inpainting, outpainting to a new aspect ratio.
Weak at
Preserving tiny details exactly (text, UI), long clips (processing windows), avoiding "shimmer".
Agent fit
Good via APIs or ComfyUI workflows; needs masks/control signals that an agent can produce with code (segmentation, depth estimation).
A4 Digital humans, talking heads, lip-sync
Mechanism
Three variants: (1) avatar platforms that turn a script into a presenter video from a trained avatar; (2) audio-driven portrait animation: an image + a speech track → a talking video; (3) lip-sync / re-dubbing: modify only the mouth region of existing footage to match new audio.
Pixels
Synthesised (fully or in the face region).
Motion
Driven by the audio (phonemes → mouth shapes, prosody → head motion) plus learned idle motion.
Control
Script, voice, avatar choice, sometimes gestures/emotion tags. Camera mostly fixed.
Consistency
Excellent for the same avatar (it is literally the same identity model).
Audio
Speech is the input (TTS or recorded); avatar platforms bundle TTS.
Strong at
Training, corporate comms, localisation into many languages, explainers with a human face.
Weak at
Full-body action, emotional nuance over long takes, uncanny-valley risk; strict consent requirements for real people's likeness and voice.
Agent fit
Good: commercial avatar platforms expose REST APIs; open-source lip-sync models run locally on a GPU.
A5 Joint audio-video generation
Mechanism
One model generates the video and the soundtrack together (or two coupled branches attend to each other), so footsteps land on impacts and lips move with generated dialogue.
Pixels / audio
Both synthesised.
Control
Dialogue in the prompt (often in quotes), sound descriptions. You cannot easily swap the voice or remix stems afterwards unless the provider gives separate tracks.
Strong at
Short cinematic moments with diegetic sound, quick social clips, dialogue scenes.
Weak at
Professional mixing (no stems), consistent narrator voice across a long video, music continuity across cuts.
Agent fit
Same API pattern as A1; the agent must decide whether to keep or strip the native audio. In a narrated documentary, native audio is usually reduced to an ambience bed or discarded. Inference
A6 World models and interactive generation
Mechanism
Autoregressive models that generate frames step-by-step in response to actions (move left, turn camera), producing navigable, persistent-ish environments in real time.
Status
Experimental for production use as of Oct 2026: impressive research previews, limited access, short memory horizons. Relevant because they hint at "virtual sets" a camera could be driven through.
Agent fit
Mostly not yet available as general production APIs.

B — Rendered scenes (code-driven graphics)

B1 2D motion graphics and explainer animation in code
Mechanism
A program describes, for every frame number t, what to draw: shapes, text, SVG, charts, images, equations. A renderer draws each frame (often a headless browser for web-based frameworks, or Cairo/OpenGL for Python ones) and an encoder writes the frames into a video file.
Pixels
Rendered (vector → raster).
Motion
Authored: interpolation between keyframes with easing curves, springs, or arbitrary functions of time.
Control
Total and frame-exact. Typography, data, brand colours are exact.
Consistency
Automatic — components and themes are reused.
Audio
Added as tracks inside the composition (narration file + timestamps drive the animation) or in post.
Strong at
Educational/math explainers, data stories, UI/product walkthrough graphics, titles, kinetic typography, social clips with captions.
Weak at
Photorealism, organic motion, characters (possible but laborious).
Agent fit
The best fit of any category. It is just code: agents write it, run it headlessly, inspect stills at chosen frame numbers, and fix with diffs. Practice
B2 3D modelling, animation and offline rendering
Mechanism
A scene graph of meshes, materials, lights and cameras; animation as keyframed properties (F-curves), rigs/skeletons, constraints, or simulation. A renderer (path tracer for realism, rasteriser for speed) computes each frame; frames are encoded to video.
Pixels
Rendered.
Motion
Authored or simulated. Camera moves are exact (paths, focal length, depth of field).
Control
Total, but you must supply assets (models, textures). Generated 3D assets (text/image-to-3D) are now an option.
Consistency
Automatic: the same rocket model is the same rocket in every shot.
Audio
None natively; added in post.
Strong at
Engineering/scientific visualisation, product renders, cutaways, exploded views, accurate trajectories.
Weak at
Cost of photorealism (asset quality, lighting skill, render time), human characters.
Agent fit
Very good when the engine is scriptable and headless (e.g. Python inside a 3D suite, a CLI render). Asset creation and aesthetic lighting remain the hard parts for agents. Inference
B3 Real-time engines (game-engine rendering)
Mechanism
Same scene concepts as B2, rendered with GPU rasterisation (+ some ray tracing) fast enough for interactive frame rates; "movie render" modes write high-quality frames offline.
Trade-off
Real-time = seconds per shot, rich asset marketplaces, virtual production; offline path tracing = higher physical accuracy, minutes per frame.
Agent fit
Medium: engines are large, GUI-centric applications. Python/remote-control APIs exist, but projects, assets and builds are heavy for an agent to manage. Inference
B4 Procedural graphics, particles and physics simulation
Mechanism
Rules and equations generate geometry and motion: particle emitters (exhaust plumes, sparks), rigid-body and fluid solvers, noise fields, L-systems, node-based procedural modelling.
Motion
Simulated — physically plausible by construction, and "correct" if the physics parameters are.
Strong at
Smoke, fire, debris, crowds, scientifically meaningful motion.
Weak at
Art direction (simulations are hard to steer to a look), compute cost of high-resolution fluids.
Agent fit
Good for parameterised setups via scripting; tuning to look good needs visual feedback cycles.
B5 Data and scientific visualisation
Mechanism
Plotting/visualisation libraries render data-driven frames (charts, fields, meshes, trajectories) and export animation.
Strong at
Truthfulness: the picture is a function of the data.
Agent fit
Excellent (ordinary Python/JS code). Styling to broadcast quality is the usual gap.
B6 Captured 3D: Gaussian splats, NeRFs, photogrammetry
Mechanism
Reconstruct a real place or object from many photos/video into a 3D representation, then render new camera paths through it.
Strong at
Photoreal fly-throughs of real places/objects with authored camera moves.
Weak at
Moving subjects, editing the scene content, artefacts at unseen angles. Emerging in production pipelines.

C — Assembly and editing

C1 Stills animated over time (pan/zoom, parallax, 2.5D)
Mechanism
Generate or source still images, then create motion at edit time: slow zoom/pan ("Ken Burns"), parallax by splitting foreground/background layers (depth estimation), or animating via I2V (A2).
Strong at
Cheap, fully controllable, consistent; standard for documentary archive stills and many faceless social channels.
Weak at
Feels static if overused.
Agent fit
Excellent (image API + FFmpeg or a code framework).
C2 Programmatic timeline assembly
Mechanism
A timeline is data: tracks of clips with in/out points, positions, transitions, effects, captions, and audio levels. A tool composites the tracks frame by frame and encodes. The timeline can be an FFmpeg filter graph, a Python/JS composition, a JSON template sent to a rendering API, or an interchange file (EDL/XML/OTIO) opened by an editor.
Control
Frame-exact timing; deterministic.
Agent fit
Excellent. This is where the agent's plan becomes a video.
C3 Template-based video APIs and "AI video maker" apps
Mechanism
Cloud services fill designed templates with your text, images and voice (JSON → MP4), or consumer apps turn a script into a stock-footage video with voiceover.
Agent fit
APIs: good. Consumer apps without APIs: poor (UI automation only).
C4 Automated editing of recorded footage
Mechanism
Analyse existing recordings with speech recognition, silence detection, scene detection, face tracking and LLM summarisation, then cut, reframe (16:9 → 9:16), caption and highlight automatically. Text-based editing (edit the transcript, the video follows) is the dominant UX.
Strong at
Podcasts, talks, interviews, tutorials, clipping long videos into shorts.
Agent fit
Excellent with open tools (ASR + FFmpeg); mixed for commercial apps (some have APIs).
C5 Screen and UI capture (product demos)
Mechanism
Record a real application session — increasingly scripted with browser automation so it is repeatable — then add zooms, cursor highlights, captions, and narration.
Agent fit
Excellent for web apps: the agent writes the automation script, records it headlessly, and re-records when the UI changes. Inference
C6 Professional non-linear editors (NLEs) with scripting
Mechanism
GUI editors used by professionals for editing, colour grading, audio mixing and finishing. Several have scripting APIs or accept timeline interchange files.
Agent fit
Medium: useful as a "finishing station" a human opens, or controlled via scripting/interchange files. The agent rarely needs the GUI if a programmatic path exists. Inference

D — Hybrid pipelines

D1–D6 The common hybrid patterns
  • D1 Per-shot mixing: the timeline alternates rendered diagrams, generated b-roll, stock footage and avatars. The most common professional pattern. Practice
  • D2 CG layout → AI restyle: block out geometry and camera in 3D (exact motion and composition), render a plain pass plus depth/edges, then use video-to-video generation to make it photoreal or stylised. Gets B's control with A's look. Practice in VFX/previs; quality varies.
  • D3 AI assets inside authored scenes: generated textures, backgrounds, 3D models, or characters imported into a code-driven scene.
  • D4 Generated plate + CG overlay: a generated cinematic background with exact labels, arrows, HUD graphics composited on top (the overlay must track the camera if it moves).
  • D5 Real footage + AI VFX: object removal, sky replacement, relighting, de-aging, dubbing of filmed material.
  • D6 Keyframe-first chains: consistent still keyframes (image model with references) → I2V per shot → edited together. The dominant method for AI "short films" in 2025-26. Practice
